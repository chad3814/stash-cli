# API Key Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Send stash's `ApiKey` header on every request the CLI makes, resolved from `STASH_API_KEY`, so the CLI works against an authenticated server without the key reaching shell history, the process table, or the CLI's own output.

**Architecture:** A new `src/auth.ts` owns key resolution, header construction, and the wording of authentication failures. The two modules that make outbound requests — `src/graphql.ts` and `src/download.ts` — call it. Nothing is threaded through the nine operations in `src/stash.ts`, and `scripts/codegen.ts` needs no change because it reaches the server through the same `request()`.

**Tech Stack:** TypeScript 7 (`tsgo`), `node:test` via `tsx`, `oxlint`, esbuild. No runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-08-05-api-key-design.md`

## Global Constraints

- **Never use the `any` type.** `unknown` only where TypeScript forces it, narrowed immediately.
- **`dependencies` in `package.json` stays empty.** `tests/bundle.test.ts` asserts this and that the bundle `require()`s only `node:` builtins.
- The API key must **never** appear in stdout, stderr, an error message, or a commit. There is **no `--api-key` flag** — a flag leaks into shell history and `ps` output.
- The header name is exactly `ApiKey`, verified against <https://docs.stashapp.cc/api/>.
- 2-space indent; semicolons always. Relative imports carry a `.js` extension though files on disk are `.ts`. Type-only imports use `import type`.
- `strict`, `noUncheckedIndexedAccess`, `noPropertyAccessFromIndexSignature`, `noUnusedLocals`, `exactOptionalPropertyTypes` are all on.
- `npm run lint` is `oxlint --deny-warnings`; a warning fails the build. `no-shadow` and `no-underscore-dangle` are active.
- `src/generated/schema.d.ts` is generated. Never hand-edit it, and do not run codegen.
- **No test may reach a real stash server.** `runCli` in `tests/cli.test.ts` already defaults `STASH_ENDPOINT` to `http://127.0.0.1:1/graphql`. The developer has a live stash on `localhost:9999`, which is also the CLI's default endpoint.
- 128 tests pass before this plan starts. None may regress.

### Three facts to design the tests around

All three were verified by experiment, not assumed:

1. **`req.headers` lowercases every name.** A stub reading `req.headers['ApiKey']` gets `undefined`, and one reading `req.headers['apikey']` cannot tell `ApiKey` from `APIKEY` or `apikey`. Since a wrong header name is one of the two failure modes the spec names, the test **must** read `req.rawHeaders`, which preserves the name as sent. `rawHeaders` is a flat array: `[name, value, name, value, ...]`.
2. **`??` does not fall through on an empty string.** So `resolveApiKey('')` returns `undefined` without consulting the environment — an explicit empty override means "no key", not "go look at `STASH_API_KEY`". This is intended; do not "fix" it.
3. **`noUnusedParameters` is on**, so a handler written `(body, req) => …` that ignores `body` fails `tsc` with TS6133. Name it `_body`: TypeScript exempts a leading underscore, and `oxlint --deny-warnings` accepts it here — both confirmed against this repo's own config. Do not work around it by referencing `body` pointlessly.

### Why no `apiKey` parameter is added to `request()` or `downloadTo()`

Coverage is split so that the transport is never tested by mutating `process.env`, which would leak between tests and make results depend on the developer's shell:

- `src/auth.ts` is unit-tested through its `override` parameter — no environment needed for the trimming, absence, and message-selection cases.
- The wiring (that `request()` actually sends what `authHeaders()` returns) is proven end to end by subprocess tests, which set the environment for the *child*. This is the established pattern: `runCli` already passes `env`.

Two tests in `tests/auth.test.ts` are the deliberate exception: reading `STASH_API_KEY` **is** the production path, so it must be covered directly. Those two set and restore the variable in a `finally`, and they are the only place in the suite that touches the environment in-process. Everything reached through the transport goes through a subprocess instead.

Adding an `apiKey` parameter to `request()` would be a fourth positional argument used only by tests, for coverage the subprocess tests already provide more convincingly.

```ts
/**
 * Authentication for stash's GraphQL API and its download endpoints.
 *
 * stash offers an API key or a session cookie. Only the key is implemented: a session
 * cannot outlive a process that runs once and exits, and stash marks cookie auth obsolete
 * as of v0.7. See docs/superpowers/specs/2026-08-05-api-key-design.md.
 *
 * The key is read from the environment rather than accepted as a flag. A flag would put it
 * in shell history and in `ps` output for every other user on the machine.
 */

/**
 * Resolves the API key from `override`, else `STASH_API_KEY`.
 *
 * Trims, and treats unset, empty, and whitespace-only alike as absent. Both halves matter:
 * `STASH_API_KEY=$(cat key.txt)` picks up a trailing newline, and a header value carrying
 * one is rejected by the HTTP layer with nothing in the message to say why.
 *
 * `??` deliberately does not fall through on an empty string, so an explicit `''` means
 * "no key" rather than "consult the environment".
 */
export function resolveApiKey(override?: string): string | undefined {
  const key = (override ?? process.env['STASH_API_KEY'])?.trim();
  return key === undefined || key === '' ? undefined : key;
}

/**
 * The header to add to a request, or an empty object when there is no key. Returning `{}`
 * rather than `{ ApiKey: '' }` keeps the anonymous case byte-identical to what the CLI
 * sent before authentication existed.
 */
export function authHeaders(apiKey?: string): Record<string, string> {
  const key = resolveApiKey(apiKey);
  return key === undefined ? {} : { ApiKey: key };
}

/**
 * An actionable message for an authentication failure, or `undefined` for any status that
 * is not one. The two cases are worded differently because the remedy differs: with no key
 * the user needs to set one, and with a key the key itself is the problem.
 *
 * Deliberately interpolates the target and nothing else — never the key, and never the
 * response body, which for a 401 is usually an HTML login page.
 */
export function authFailureMessage(
  status: number,
  target: string,
  apiKey?: string,
): string | undefined {
  if (status !== 401 && status !== 403) {
    return undefined;
  }
  return resolveApiKey(apiKey) === undefined
    ? `${target} requires authentication; set STASH_API_KEY (stash: Settings > Security > Authentication)`
    : `${target} rejected the API key in STASH_API_KEY; it may be revoked, or from a different server`;
}
```

```ts
test('a download carries the ApiKey header', async () => {
  const directory = await mkdtemp(join(tmpdir(), 'stash-download-'));
  let downloadSawKey = false;
  const server = createServer((req, res) => {
    if (req.url === '/graphql') {
      req.on('data', () => {});
      req.on('end', () => {
        res.writeHead(200, { 'content-type': 'application/json' });
        res.end(JSON.stringify({ data: { backupDatabase: '/downloadBackup/stash-go.sqlite' } }));
      });
      return;
    }
    // The download is a second request to the same origin. A server that authenticates
    // the mutation authenticates this too, so refuse it without the header.
    downloadSawKey = req.rawHeaders.some((entry) => entry.toLowerCase() === 'apikey');
    if (!downloadSawKey) {
      res.writeHead(401);
      res.end('Unauthorized');
      return;
    }
    res.writeHead(200);
    res.end('BACKUP');
  });
  await new Promise<void>((ready) => { server.listen(0, '127.0.0.1', ready); });
  const address = server.address();
  if (address === null || typeof address === 'string') { throw new Error('no port'); }
  try {
    const result = await run(process.execPath, ['--import', tsxLoader, resolve(root, 'index.ts'), 'backup', '--download'], directory, { ...process.env, STASH_ENDPOINT: `http://127.0.0.1:${address.port.toString(10)}/graphql`, STASH_API_KEY: 'test-key-value' });
    assert.equal(result.code, 0, result.stderr);
    assert.ok(downloadSawKey, 'the download request must carry the key, not just the mutation');
    assert.equal(await readFile(join(directory, 'stash-go.sqlite'), 'utf8'), 'BACKUP');
  } finally {
    await new Promise<void>((closed) => { server.close(() => { closed(); }); });
  }
});
```

```ts
test('the api key never reaches stdout or stderr, on any path', async () => {
  const SECRET = 'zzz-unmistakable-key-value-9f3a-zzz';
  // Each case is a different way the CLI can fail while holding the key. A server that
  // echoes the key back is included deliberately: the CLI interpolates response bodies
  // into its error messages, so this is the most plausible route to a disclosure.
  const cases: { name: string; handler: () => StubReply }[] = [
    { name: '401', handler: () => ({ status: 401, raw: 'Unauthorized' }) },
    { name: '500 with the key echoed back', handler: () => ({ status: 500, raw: `rejected key ${SECRET}` }) },
```
